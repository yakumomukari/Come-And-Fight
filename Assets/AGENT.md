# 《废话少说，来决斗吧！》UI 反馈优化任务

## 任务目标

在 Unity 项目 `yakumomukari/Come-And-Fight` 的最新 `main` 分支上，补全白模 MVP 的行动选择、双方行动公开和结算反馈。

本次任务只解决一个问题：玩家必须能够立即看懂“自己选择了什么、对手选择了什么、为什么发生当前结算”。

不要扩展玩法，不要重写规则，不要制作正式美术。

## 开始前检查

1. 拉取并检查最新 `main` 分支，不要默认仓库仍停留在旧提交。
2. 阅读以下文件：
   - `Assets/Scripts/DuelMvp/DuelGame.cs`
   - `Assets/Scripts/DuelMvp/DuelUI.cs`
   - `Assets/Scripts/DuelMvp/TurnResolver.cs`
   - `Assets/Scripts/Editor/DuelSceneUIInstaller.cs`
   - `Assets/Scenes/SampleScene.unity`
   - `Assets/《废话少说，来决斗吧！》项目设计文档 v0.3.md`
3. 保留规则层与表现层分离：`TurnResolver` 只负责确定性结算，不得依赖动画、物理碰撞或 UI。
4. 检查工作区已有修改，不得覆盖无关改动。

## 必须实现

### 1. 玩家选择反馈

- 玩家 A 选择行动后，对应按钮必须立即进入明显的选中状态。
- 未选择的三个按钮必须表现为不可再次选择，但仍需保留可读性。
- 在本回合结算完成前保持选中状态。
- UI 必须明确显示具体选择，例如：`已选择：击剑`，不能只显示 `A 已锁定`。
- 键盘输入和鼠标点击必须产生完全一致的反馈。

### 2. 双方行动公开

- 双方均完成选择或倒计时结束后，进入独立的行动公开阶段。
- 清晰显示：`A：击剑  |  B：招架`。
- 公开阶段持续约 `0.4～0.6` 秒，期间禁止输入。
- 对战 AI 时，在公开阶段之前不得展示 AI 的选择。
- 本地双人时，在公开阶段之前不得展示另一方的具体选择。

### 3. 白模动作区分

使用现有几何白模完成最低成本表现，不引入正式角色素材：

- 前进：向前移动一格。
- 后退：向后移动一格。
- 击剑：剑或角色快速向攻击方向伸出，再收回。
- 招架：角色短暂变色或剑产生明显格挡姿态。

动画只表现已经计算出的结果，不参与规则判定。

### 4. 结算事件反馈

至少区分以下事件：

- 击剑命中；
- 招架成功；
- 前进推动招架者；
- 双方前进相撞；
- 坠落；
- 双方同时命中；
- 进入死斗；
- 被火焰吞噬；
- 得分；
- 比赛结束。

可使用颜色闪烁、短促抖动、剑伸缩、击退位移和文字组合实现。不得只依赖一行瞬间消失的状态文字。

### 5. 节奏调整

- 行动公开后再播放结算动画。
- 结算结果至少保持 `1.0` 秒，建议 `1.2` 秒。
- 结果展示结束后才恢复按钮并开始下一回合的 2 秒倒计时。
- 比赛结束后保持最终结果，直到玩家按 `R` 重开。

## 实现约束

- 使用 Unity `2022.3.62f2c1` 可用 API。
- 保留当前 UGUI 方案，不迁移 UI Toolkit。
- 不增加第三方包。
- 不引入 ECS、状态机框架、事件总线或新的数据驱动系统。
- 不把 UI、音效或动画引用塞进 `TurnResolver`。
- 不改变四种行动、命中范围、计分、胜利条件、20 回合死斗等规则。
- 不顺手整理整个项目或批量格式化无关文件。
- 场景中的固定 UI 必须保持序列化；不要重新改回运行时创建 UI。
- 若新增 UI 引用，应同步更新场景或编辑器安装器，并确保现有场景能直接运行。
- C# 脚本允许保留必要注释。

## 推荐结构

可以对现有表现层做小规模调整：

- `DuelGame`：维护选择、公开、结算、结果停留等阶段，并驱动白模动画。
- `DuelUI`：读取表现状态，刷新按钮、选择文字、公开文字和结算文字。
- `TurnResult`：仅在确有必要时增加不影响规则的结算标记；优先复用现有字段。
- `DuelSceneUIInstaller`：仅负责生成和绑定固定场景 UI。

不要为了四个动作建立复杂通用动画架构。当前目标是快速验证核心玩法。

## 验收标准

完成后必须逐项验证：

1. 点击或按键选择任意行动后，玩家能在一帧内看见具体选择。
2. 同一回合不能重复选择或更改选择。
3. 公开前看不到对手行动，公开时能同时看见双方行动。
4. 玩家不读结算文字，也能从白模表现大致区分前进、后退、击剑和招架。
5. 击中、招架、推动、碰撞和坠落具有不同反馈。
6. 结果不会在玩家看清前被下一回合覆盖。
7. 下一回合开始时按钮、选中状态和提示均正确重置。
8. 玩家 VS AI 与本地双人模式均可正常完成一场比赛。
9. `R` 重开和 `F1` 切换模式后 UI 状态不会残留。
10. 现有 `TurnResolverTests` 全部通过。
11. 如新增表现状态或结算字段，应补充必要测试，但不要为纯动画细节写脆弱测试。

3. 实际执行的测试及结果；
4. 无法自动验证的 Unity 场景表现；
